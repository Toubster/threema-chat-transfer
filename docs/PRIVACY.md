# Datenschutz / Privacy

[Deutsch](#deutsch) · [English](#english)

## Deutsch

### Kurz

Chat Transfer for Threema läuft vollständig auf Ihrem Mac. Es gibt kein Konto, keinen Server, keine Nutzungsdaten, keinen
Absturzberichts-Dienst und keine Update-Prüfung. Ihre Chats verlassen Ihren Mac nicht – außer über das USB-Kabel zu
Ihrem eigenen iPhone.

### Was verarbeitet wird

| Daten | Woher | Wozu |
|---|---|---|
| Android-Datensicherung von Threema (Chats, Medien, Kontakte) | Datei, die Sie auswählen | Verlauf lesen und für das iPhone vorbereiten |
| iPhone-Sicherungen (vorher und nachher, verschlüsselt) | Ihr iPhone per USB | Threema-Daten ergänzen, Übertragungspaket bauen, Vorher-nachher-Vergleich |
| Passwörter (Android-Sicherung, iPhone-Sicherung) | Ihre Eingabe bzw. von Chat Transfer for Threema erzeugt | Sicherungen öffnen |
| Geräteangaben (Modell, iOS-Version, freier Speicher, Akku) | Ihr iPhone, nur lesend | Prüfungen |

### Wo es liegt

Ein Sitzungsordner unter `~/Library/Application Support/Chat Transfer for Threema/sessions/<Kennung>/` (Sie können einen anderen Ort auf
einem APFS-Laufwerk wählen):

- nur für Ihren Benutzer lesbar (`0700`), von Time Machine ausgeschlossen, von Spotlight nicht durchsucht;
- `android/`: der vorbereitete Verlauf (**lesbar**), Medien, eine Liste fehlender Kontakte;
- `ios/`: die iPhone-Sicherungen (verschlüsselt);
- `work/`: Arbeitskopien (lesbar);
- `reports/`, `logs/`: nur Codes und Zählungen bzw. ein bereinigtes Fehlerprotokoll.

Ist FileVault aus, warnt Chat Transfer for Threema gleich zu Beginn, weil lesbare Kopien auf dem Mac liegen.

### Passwörter

- Das Passwort der Android-Sicherung und ein von Ihnen eingetipptes iPhone-Sicherungs-Passwort bleiben nur im
  Arbeitsspeicher. Sie werden nie in Dateien, Protokolle, Berichte oder Kommandozeilen geschrieben.
- Ein von Chat Transfer for Threema erzeugtes iPhone-Sicherungs-Passwort wird – wenn Sie zustimmen – im Schlüsselbund Ihres Mac gesichert
  („Chat Transfer for Threema – Backup-Passwort“), bis Sie es löschen.

### Aufräumen

Am Ende bietet Chat Transfer for Threema an, die lesbaren Chat-Kopien zu löschen (empfohlen). Die Sicherheitskopie Ihres iPhones können
Sie 7 Tage behalten; danach schlägt Chat Transfer for Threema das Löschen erneut vor. Die Android-Sicherungsdateien fasst Chat Transfer for Threema nicht an.
Deinstallation: Anleitung, Kapitel 9.

### Diagnosebericht

Nur wenn Sie auf „Diagnosebericht speichern“ klicken, mit Vorschau „Das steht drin“, als Datei auf Ihrem Mac. Inhalt:
Codes, Zählungen, Dauern, öffentliche Versionsnummern (iOS, Threema, Chat Transfer for Threema), Prüfergebnisse und gehashte Kennungen
mit einem neuen Zufallswert je Bericht. **Nicht** enthalten: Namen, Threema-IDs, Telefonnummern, E-Mail-Adressen,
Nachrichten, Dateinamen, Gerätename, Seriennummern, das Fehlerprotokoll. Chat Transfer for Threema lädt nie etwas hoch; Sie entscheiden,
ob Sie den Bericht an ein Issue anhängen.

### Anzeige

Chat Transfer for Threema zeigt nie den Gerätenamen Ihres iPhones (er enthält oft einen Vornamen), sondern nur Modell und iOS-Version.
Threema-IDs erscheinen nur in der Liste der Personen, die Sie als Kontakt hinzufügen sollen.

## English

### In short

Chat Transfer for Threema runs entirely on your Mac. There is no account, no server, no telemetry, no crash reporter and no update check.
Your chats never leave your Mac, except over the USB cable to your own iPhone.

### What is processed

| Data | From | Purpose |
|---|---|---|
| Threema Android data backup (chats, media, contacts) | the file you choose | read the history and prepare it for the iPhone |
| iPhone backups (before and after, encrypted) | your iPhone over USB | add the Threema data, build the transfer package, compare before and after |
| Passwords (Android backup, iPhone backup) | typed by you or generated by Chat Transfer for Threema | open the backups |
| Device facts (model, iOS version, free space, battery) | your iPhone, read-only | checks |

### Where it is stored

A session folder in `~/Library/Application Support/Chat Transfer for Threema/sessions/<id>/` (you can choose another location on an APFS
drive):

- readable only by your user (`0700`), excluded from Time Machine, not indexed by Spotlight;
- `android/`: the prepared history (**readable**), media, a list of missing contacts;
- `ios/`: the iPhone backups (encrypted);
- `work/`: working copies (readable);
- `reports/`, `logs/`: codes and counts only, and a redacted debug log.

If FileVault is off, Chat Transfer for Threema warns you at the start, because readable copies are on the Mac.

### Passwords

- The Android backup password and an iPhone backup password you type are kept in memory only. They are never written
  to files, logs, reports or command lines.
- An iPhone backup password generated by Chat Transfer for Threema is saved in your Mac's keychain if you agree (item name
  "Chat Transfer for Threema – Backup-Passwort", in every language), until you delete it.

### Cleaning up

At the end Chat Transfer for Threema offers to delete the readable chat copies (recommended). You can keep the safety copy of your iPhone
for 7 days; then Chat Transfer for Threema suggests deleting it again. Chat Transfer for Threema never touches the Android backup files. Uninstalling: user
guide, chapter 9.

### Diagnostic report

Only when you click "Save diagnostic report", with a preview "What is in it", as a file on your Mac. Content: codes,
counts, durations, public version numbers (iOS, Threema, Chat Transfer for Threema), check results and hashed identifiers with a new random
salt per report. **Not** included: names, Threema IDs, phone numbers, e-mail addresses, messages, file names, the
device name, serial numbers, the debug log. Chat Transfer for Threema never uploads anything; you decide whether to attach the report to
an issue.

### On screen

Chat Transfer for Threema never shows your iPhone's device name (it often contains a first name), only the model and iOS version. Threema
IDs appear only in the list of people you need to add as contacts.

## Technical notes (for reviewers)

- **Engine output.** stdout events are validated against `core/schema/events.v1.json`; free text does not exist.
  Allowed values: numbers, booleans, enums, codes, salted hashes (`h:` + 8 hex, HMAC-SHA256 with a per-session salt),
  timestamps, public version numbers. Data the UI must show (the missing contacts of S07) is a `0600` file in the
  session folder; the event names only its key.
- **Logs.** Third-party output (pymobiledevice3, importer) goes to stderr → `logs/debug.log`, filtered by
  `tmcore/redact.py`: home directory → `~`, UDID and ECID patterns, e-mail addresses, phone numbers, Threema-ID
  patterns, the device name from lockdown, backup file names. Exceptions are reported as code, exception class and
  `module:line`, never with their message. `debug.log` is never part of a diagnostic report.
- **Canary test.** `fixtures/canaries.json` holds a contact name, group name, message text, Threema ID `ZZCANARY`,
  device name, UDID, e-mail address and password. After every fixture end-to-end run, all events, reports, logs,
  `session.json`/`engine.json` and the diagnostic report are searched for these values byte by byte, also in UTF-16
  and Base64. Zero hits allowed (except the fixture input files and `missing-senders.json`).
- **Repository.** `scripts/scrub_check.py` keeps real data out of the repository (see SECURITY-MODEL.md §5.7).
  Screenshots come only from the demo mode (marker `tm-demo=1`) or are reviewed device photos (`tm-reviewed=1`).
